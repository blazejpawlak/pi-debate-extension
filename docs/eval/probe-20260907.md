## True high-severity issues found (my judgement)

### Baseline — 4 verified, 4 asserted-then-self-downgraded

Verified against this machine with actual commands:

1. **`multica-ctl freeze` does not cover `ai.multica.binary-watchdog`**, which runs every
   600s and calls `FORCE=1 multica-ctl restart` → `launchctl load -w`, **clearing the
   disabled override `freeze` just set**. So frozen daemons resurrect after the "final"
   snapshot. Traced through three files to prove the mechanism.
2. **Two Herdr LaunchAgents exist** (`dev.herdr.collie`, `dev.herdr.collie-vpn-hosts`);
   TASK-030 unloads only the first. The second re-executes on a 30s `StartInterval`.
3. **Port attribution is wrong**: 8788 is Homebrew Caddy, not Multica (which is on 3443);
   and **KSeF has no listening port at all** (`sync --watch` with `KeepAlive=true`), so
   the plan's "verify the port is absent" check passes vacuously or hangs.
4. **`pg-backup` (02:30), `stale-session-reaper` (300s), `log-rotate`,
   `quota-policy-audit` all remain armed after `freeze`** — the 02:30 job can overwrite
   the good pre-quiescence dump with a failed one.

Plus a genuinely useful self-critique: it downgraded its own #6 (FileVault ordering) and
#7 (VMware/Migration Assistant categories) as unfalsified-on-hardware, admitted it
"should have run the `mdfind` I proposed", and listed four things it missed — including
that **both Time Machine destinations are SMB network shares**, and that
`stop --kill-node` does a system-wide `pkill -9 -x node` that would kill KSeF.

### Debate — 3 high-severity, none verified

- **B1**: no write barrier spanning the PG dump and uploads archive. `evidence: null`.
- **B2**: TASK-030–031 verify cessation but not *persistent* restart suppression.
  `evidence: null`.
- **B3**: destination pre-login gate misses startup mechanisms outside the quarantined

These are real and well-posed — B2 is arguably the same insight as the baseline's #1, and

The baseline made the same class of claim and then went and checked it.

## Why the debate underperformed

**1. The Skeptic barely used its tools — 3 bash calls vs 28.** This is the whole ballgame.
D5's premise is "a Skeptic that can actually run `tmutil compare` is the difference
between a verified claim and a rhetorical one." The Skeptic had bash and chose rhetoric.
Its persona says "Run the tests you can" but its incentives are dominated by the mission's
hard requirement to produce ≥3 flaws with a severity and a test — writing a test string is
cheap, running it is not.

**2. `disputed` closes the gate, so R3 never ran (protocol defect).** §5's gate is "no
claim with `status=open` AND `severity ∈ {high, critical}`". In R2 the Skeptic moved its
own three high-severity claims from `open` to `disputed` — which is permitted without
`refutedPremise` (§13.22c, deliberately, so the minority report is reachable) — and that
**emptied the open-high set and closed the gate**. The one mechanism designed to force
more scrutiny of unresolved high-severity items was switched off by the party those items
belonged to, using a transition that requires no evidence at all. The run reported "No
unresolved high-severity claims" while holding three unverified high-severity claims.

**3. The Ideator produced volume, not verification.** 11 of 14 claims are the Ideator's,
all `medium`, all single-message turns with zero tool calls. A4/A7/A8 are decent
document-level observations (resync window, undocumented preconditions, free-space
ordering) but nothing needed two models to find.

**4. The judge over-trusted the ledger.** It returned confidence **0.9** on a ledger whose
every high-severity claim had `evidence: null`, and its own instructions say "A claim
resolved without evidence remains a risk." It weighted the *structure* of the ledger over
the absence of evidence in it. It also read A11 (an Ideator concession) as corroboration —
close to the "agreement is not evidence" failure it was explicitly told to avoid.

**The lint caught all of this and nobody acted on it:** `conf_no_evidence` fired **6
times** and `skeptic_under_min_flaws` once. The instrumentation is right; it is currently
advisory only.

## What is genuinely working

- Protocol mechanics: 5 turns, correct order, 0 repairs, clean merge, correct ID
  namespacing, gate evaluated as specified.
- Cost accounting: $0.6165 summed across 16 requests, per-turn attribution in the verdict.
- **Prompt caching: 60.3% cache read**, confirming §6.3's stable-prefix ordering pays off.
- The claim ledger is a better *artifact* than the baseline's prose — sortable, citable,
  with per-claim status history. If the claims were evidenced it would be strictly better.
- Anonymization held: judge saw no `author`, no `history.by`.
- Verdict had all 7 §8.4 sections, cited claim ids, and a real minority report.

---

## Recommended tuning before WP6 (in order of expected effect)

1. **Make the gate ignore evidence-free status changes.** A high/critical claim moved
   `open → disputed` with no new `evidence` should still count as open for gate purposes.
   Otherwise the Skeptic can always end the debate early. Cheap, mechanical, high impact.
2. **Require evidence for high/critical claims, or auto-demote them.** A claim asserting
   `severity: high` with `evidence: null` should either be demoted to `medium` or be
   rejected with a repair prompt ("you asserted high severity without running your own
   test; run it or lower the severity"). Turn the existing `conf_no_evidence` lint from
   advisory into enforcing.
3. **Reward executed tests in the Skeptic mission.** State a floor: at least N of your
   flaws must carry command output as evidence. The current mission asks for tests as
   *strings*, which is exactly what it got.
4. **Tell the judge to discount unevidenced claims explicitly**, and cap confidence when
   the lint contains `conf_no_evidence`. A 0.9 confidence over a zero-evidence ledger is
   the single most misleading number in the output.
5. Consider dropping the Ideator to a cheaper model. It contributed 11 medium claims for
   $0.029 total and no verification; the Skeptic is where the value and the cost both are.

---

## Verdict on the idea

Not dead, but not yet earning its cost. The **structure** (ledger, anonymized judge,
severity gate, cost enforcement) is sound and demonstrably works. The **behaviour** the
structure is supposed to induce — adversarial *verification* — did not happen, and the
protocol let the Skeptic close the gate on its own unverified claims.

Fixes 1, 2 and 4 are small, mechanical, and target exactly the observed failures. They
should be made and this probe re-run before proceeding to WP6. If a re-run still loses to
a single opus call with bash, the honest conclusion is that a strong model with tools and
a self-critique pass is sufficient for this task class, and the debate should be dropped.
