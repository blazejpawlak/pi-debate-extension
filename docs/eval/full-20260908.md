## 3. A protocol defect this run exposed and fixed (§13.49)

**The first WP8 attempt (`20260907-234500-wp8`) closed the gate at R2 and reported
`openHigh: 0` while five high-severity findings sat unresolved.**

Cause: `isUnsettled` treated `disputed` + evidence as *settled*. §13.34 had closed the
complement (disputed *without* evidence), so the Skeptic found the remaining move — dispute
your own evidenced finding and it leaves the gate. All five high-severity claims vanished
and the debate stopped a round early.

`disputed` means the parties disagree, which is unresolved **by definition** — §8.4 says so
itself ("the minority report is never empty when any claim is `disputed`"). Fixed: only
`resolved` + evidence, or `withdrawn`, settles a claim.

Effect, measured by re-running the identical seed:

| | before fix | after fix |
|---|---|---|
| Rounds | 2 | **3** |
| Claims | 19 | **27** |
| Reported open high | **0 (false)** | **8** |

Without this, WP8 would have recorded a *better-looking* result — fewer open items, faster,
cheaper — that was simply wrong. Two prior §13 entries (34, 35) are the same lesson: the
protocol's failure mode is making the output look cleaner than reality.

## 4. Cache and cost accounting

Cache read 62.2% (debate) vs 82.7% (baseline). The debate's is lower because each turn
sends a differently-composed mission (ledger state changes), while the baseline reuses one
growing prefix. On a metered provider this is what made the debate disproportionately
expensive; on IBM it costs nothing but does explain the 2.0× token ratio.

Both arms reported `cost.total = 0` with real token usage, so `costTrusted: false`
propagated correctly and every verdict row is marked `$0.0000 (?)`. **No run presented a
fake $0.00 as a real figure** — the §13.19 machinery worked as designed on the case it was
written for.

## 5. Honest notes on this evaluation

- **The baseline needed a retry.** Its first attempt died after 17m41s with
  `Request timed out` then three `Connection error`s — 5 assistant messages, 1 tool call,
  no output. The provider tested healthy immediately afterwards, so it was a transient blip
  (§13.38's exact pattern). Reported rather than quietly re-run.
- **The comparison is single-shot per arm.** One debate run and one baseline run on one
  seed. The topic-overlap table is a keyword analysis I performed, not a blind grading, and
  I am the same agent that built the system — treat the unique-findings counts as
  indicative, not as a measurement.
- **Wall clock favours the baseline more than the table suggests**: 10m27s vs 5m54s, and
  the debate is 3 sequential rounds that cannot be parallelised past R1.
- **`skeptic_under_min_flaws` lint fired**, meaning at least one Skeptic turn produced
  fewer than `minFlaws` new flaws — expected by R3 when the obvious ground is covered.

## 6. Decision and reasoning

**KEEP** — with the caveat that the baseline is a genuinely strong alternative and the
debate is not strictly better.

For keeping it:
1. **The economic objection is gone.** $0.00 vs $0.00 on the `ibm` tier. WP5's 16.6× was
   the single strongest argument against, and it no longer applies.
2. **Independent corroboration at scale.** 7 of 10 topics found twice, by different model
   families, with executed evidence. For an irreversible migration that is worth more than
   either arm's raw finding count.
3. **The adversarial pass produces findings that cannot otherwise exist.** B8 and B9
   critique the *proposed fixes*. A single-pass reviewer has no proposal to attack.
4. **The ledger is a better artifact.** 27 claims with per-claim evidence, status history,
   and ids — versus prose. §7 of the verdict is auditable.

Against, stated plainly:
1. **The baseline found 3 real things the debate missed**, two of them simple facts about
   the machine. 7 findings for 339K tokens and 6 minutes is excellent value.
2. **2.0× tokens, 1.8× wall clock**, and on any metered provider the cost gap returns.
3. **Verdict quality depends on protocol correctness**, and this very run shipped with a
   gate defect that would have silently understated risk. That is the third such defect
   (§13.34, §13.35, §13.49).

**Recommendation:** keep it as an explicit `/debate`, default to `tier: "ibm"` so invoking
it is free, and **run the baseline too when the decision is irreversible** — they are
complementary, and the union of the two arms (10 topics) is materially better than either
alone. Do not make it automatic, and do not present it as a replacement for a strong
single-model review.

**§4.1's cost table should now be rewritten** against these numbers rather than the
original $1–2/turn projection, which was wrong by an order of magnitude in both directions
depending on provider.
